# QA Gate

## Задача

        Проверь код Разработчика на соответствие архитектурному документу Архитектора.

        ЧТО ПРОВЕРЯТЬ:
        1. **Соответствие архитектуре**: все ли компоненты реализованы? Нет ли лишнего?
        2. **Безопасность**: SQL-инъекции, XSS, утечки секретов, небезопасные зависимости
        3. **Обработка ошибок**: все ли исключения обработаны? Нет ли голых try/except?
        4. **Валидация**: проверяются ли входные данные на всех endpoint-ах?
        5. **Тесты**: есть ли они? Покрывают ли основные сценарии?
        6. **Style guide**: PEP 8, нейминг, типизация

        ФОРМАТ ОТВЕТА:
        Для каждой найденной проблемы:
        - Приоритет: 🔴 (критично — блокирует запуск) / 🟡 (важно — нужно исправить) / 🟢 (минор — можно так)
        - Файл и строка (если применимо)
        - Описание проблемы
        - Предложение по исправлению

        В конце: ИТОГОВЫЙ ВЕРДИКТ — ✅ Go (нет критических проблем) или ❌ No-Go (требуются правки).
        Если No-Go — перечисли КОНКРЕТНЫЕ файлы и строки, которые нужно исправить.

# Отчёт о проверке кода URL Shortener Microservice

## 🔴 Критические проблемы

### 1. 🔴 Несоответствие API-контракту: отсутствует префикс `/v1` в архитектурном документе
**Файл:** `app/api/v1/router.py`, строка 16
**Описание:** Архитектурный документ (раздел 5) определяет endpoint-ы без префикса `/v1` (например, `POST /shorten`, `GET /{short_code}`), но реализация использует `prefix="/v1"`. Это нарушает контракт API.
**Исправление:** Убрать префикс `/v1` из роутера или согласовать с Архитектором изменение контракта.

### 2. 🔴 Race condition в генерации short_code
**Файл:** `app/services/url_service.py`, строки 80-95
**Описание:** Генерация short_code использует `time.time() * 1000 % 10**10` как sequence_number, что не гарантирует уникальность при конкурентных запросах. Проверка `get_by_short_code` и создание записи не атомарны — между ними может произойти вставка с таким же кодом.
**Исправление:** Использовать PostgreSQL sequence или `INSERT ... ON CONFLICT DO NOTHING` с retry.

### 3. 🔴 Отсутствие обработки ошибок при недоступности Redis
**Файл:** `app/services/cache_service.py`, строка 60
**Описание:** При открытии circuit breaker (`_circuit_open = True`) он никогда не закрывается. После 3 ошибок Redis становится недоступным навсегда до перезапуска сервиса.
**Исправление:** Добавить механизм half-open состояния с периодическими проверками (например, через 30 секунд).

### 4. 🔴 Утечка секретов в docker-compose.yml
**Файл:** `docker-compose.yml`, строки 12-14
**Описание:** Пароль БД `shortener_pass` и другие секреты указаны в открытом виде. Это нарушает требование архитектурного документа (раздел 6.1) о хранении секретов только в переменных окружения.
**Исправление:** Использовать `.env` файл и ссылаться на переменные через `${DATABASE_PASSWORD}`.

### 5. 🔴 Отсутствие валидации short_code в endpoint-ах
**Файлы:** `app/api/v1/redirect.py` (строка 40), `app/api/v1/stats.py` (строка 40), `app/api/v1/delete.py` (строка 40)
**Описание:** `short_code` принимается как `str` без валидации. Возможны SQL-инъекции через path parameter (хотя SQLAlchemy экранирует, но это плохая практика) и XSS через ответы с ошибками.
**Исправление:** Добавить Pydantic-модель с `@field_validator` для short_code (только base62 символы, длина 6-10).

### 6. 🔴 Отсутствие rate limiting на endpoint-ах
**Файлы:** `app/api/v1/shorten.py`, `app/api/v1/redirect.py`, `app/api/v1/stats.py`, `app/api/v1/delete.py`
**Описание:** Архитектурный документ (раздел 6.1) требует rate limiting: 30/мин для POST /shorten и 100/мин для остальных. В коде rate limiter настроен глобально, но не применён к конкретным endpoint-ам через декораторы `@limiter.limit()`.
**Исправление:** Добавить декораторы `@limiter.limit(settings.rate_limit_shorten)` на POST /shorten и `@limiter.limit(settings.rate_limit_default)` на остальные.

### 7. 🔴 Отсутствие проверки на уже удалённый URL в DELETE
**Файл:** `app/services/url_service.py`, строки 175-185
**Описание:** Метод `delete_url` вызывает `soft_delete`, который не проверяет `is_deleted` перед обновлением. Хотя есть проверка в `delete_url`, она дублируется, но в `soft_delete` нет атомарной проверки.
**Исправление:** Использовать `UPDATE ... WHERE is_deleted = false` и проверять количество обновлённых строк.

### 8. 🔴 Небезопасная генерация short_code без коллизий
**Файл:** `app/services/url_service.py`, строки 85-95
**Описание:** Цикл проверки коллизий использует `get_by_short_code` + `create`, что не атомарно. При высокой нагрузке возможны дубликаты.
**Исправление:** Использовать `INSERT ... ON CONFLICT DO NOTHING` или `SELECT ... FOR UPDATE` в транзакции.

## 🟡 Важные проблемы

### 9. 🟡 Несоответствие архитектуре: отсутствует синхронизация счётчиков из Redis в PostgreSQL
**Файл:** `app/services/url_service.py`
**Описание:** Архитектурный документ (раздел 6.2) требует "периодическую синхронизацию в PostgreSQL (background task каждые 60 секунд)". В коде счётчики хранятся только в Redis и никогда не синхронизируются в БД.
**Исправление:** Добавить background task (через `asyncio.create_task` в lifespan) для периодической синхронизации.

### 10. 🟡 Отсутствует обработка 410 Gone для истекших ссылок
**Файл:** `app/api/v1/redirect.py`, строка 40
**Описание:** Архитектурный документ (раздел 5, GET /{short_code}) требует возвращать `410 Gone` для истекших ссылок. В коде `get_original_url` выбрасывает `URLExpiredException` (код 410), но в endpoint-е нет соответствующего response в `responses`.
**Исправление:** Добавить `410: {"description": "URL has expired"}` в responses декоратора.

### 11. 🟡 Отсутствует обработка 409 Conflict для уже удалённых URL в DELETE
**Файл:** `app/api/v1/delete.py`, строка 40
**Описание:** Архитектурный документ (раздел 5, DELETE /{short_code}) требует `409 Conflict` для уже удалённых. В коде `delete_url` выбрасывает `URLAlreadyDeletedException` (код 409), но в responses указано только `409: {"description": "URL already deleted"}` — это неполное описание.
**Исправление:** Дополнить документацию.

### 12. 🟡 Неправильное использование статус-кода для дубликатов
**Файл:** `app/core/exceptions.py`, строка 46
**Описание:** `URLAlreadyExistsException` использует статус-код 409, что соответствует архитектуре. Но в архитектурном документе сказано "возвращается существующий short_code", а в реализации выбрасывается исключение без возврата существующего кода.
**Исправление:** В `shorten_url` при обнаружении дубликата возвращать существующий short_code, а не просто ошибку.

### 13. 🟡 Отсутствует проверка длины short_code в модели
**Файл:** `app/models/url.py`, строка 37
**Описание:** Поле `short_code` имеет тип `String(10)`, но нет валидации на уровне Pydantic или SQLAlchemy, что код действительно состоит из 6 символов (как указано в архитектуре).
**Исправление:** Добавить `@validates('short_code')` или constraint в БД.

### 14. 🟡 Небезопасное логирование URL
**Файл:** `app/api/v1/shorten.py`, строка 42
**Описание:** Логируется `body.url[:50]`, что может содержать чувствительные данные (токены в query parameters). Архитектурный документ (раздел 6.1) требует "не логируем original_url целиком".
**Исправление:** Логировать только short_code и метаданные, URL логировать только в debug-режиме.

### 15. 🟡 Отсутствует CORS middleware при пустом списке origins
**Файл:** `app/main.py`, строки 90-97
**Описание:** Если `ALLOWED_ORIGINS` пуст, CORS middleware не добавляется. Это может вызвать проблемы с браузерами при использовании Swagger UI.
**Исправление:** Добавить CORS middleware с `allow_origins=["*"]` для development или настроить по умолчанию.

### 16. 🟡 Неправильная обработка ошибок в health check
**Файл:** `app/main.py`, строка 120
**Описание:** `await session.execute("SELECT 1")` — это строка, а не текст SQL. Должно быть `text("SELECT 1")`.
**Исправление:** Использовать `from sqlalchemy import text` и `await session.execute(text("SELECT 1"))`.

### 17. 🟡 Отсутствует timeout для Redis операций
**Файл:** `app/services/cache_service.py`, строка 60
**Описание:** `asyncio.wait_for` используется только в `_execute_with_fallback`, но не в `is_healthy`. При зависшем Redis health check будет висеть бесконечно.
**Исправление:** Добавить timeout в `is_healthy`.

## 🟢 Минорные проблемы

### 18. 🟢 Несоответствие нейминга: `short_code` vs `shortCode` в тестах
**Файлы:** `tests/integration/test_*.py`

### 19. 🟢 Отсутствует типизация в некоторых методах
**Файл:** `app/services/cache_service.py`, строка 40
**Описание:** Метод `_execute_with_fallback` использует `Any` для `operation`, хотя можно использовать `Callable[..., Awaitable[Any]]`.
**Исправление:** Добавить более точную типизацию.

### 20. 🟢 Неиспользуемый импорт в `app/services/code_generator.py`
**Файл:** `app/services/code_generator.py`, строка 5
**Описание:** Импортирован `secrets`, но используется только в `_generate_random_suffix`. Это нормально, но можно оптимизировать.

### 21. 🟢 Отсутствует docstring в `MockRedis` и `MockPipeline`
**Файл:** `tests/conftest.py`, строки 60-120
**Описание:** Моки не имеют docstring-ов, что затрудняет понимание их поведения.
**Исправление:** Добавить docstring-и.

### 22. 🟢 Неполное покрытие тестами
**Файлы:** `tests/`
**Описание:** Отсутствуют тесты для:
- `CacheService` (unit)

- SSRF protection (интеграционные)

### 23. 🟢 Отсутствует проверка на expired URL в тестах
**Файл:** `tests/integration/test_redirect.py`
**Описание:** Нет теста для сценария `410 Gone` (истекшая ссылка).

### 24. 🟢 Несоответствие версий в requirements.txt
**Файл:** `requirements.txt`
**Описание:** Указаны конкретные версии, но архитектурный документ (раздел 2) указывает минимальные версии (например, `fastapi==0.110+`). Лучше использовать `>=` для совместимости.
