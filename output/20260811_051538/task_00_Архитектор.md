# Архитектурный документ: TODO REST API

## 1. Обзор

Система представляет собой минималистичный REST API для управления списком задач (TODO). Приложение позволяет создавать задачи, просматривать список всех задач, отмечать задачу как выполненную и удалять задачу. Функциональность намеренно ограничена базовым CRUD-набором без аутентификации, категорий, тегов и прочих расширений.

**Ключевые сценарии использования:**

1. **Создание задачи** — клиент отправляет POST-запрос с текстом задачи, сервер возвращает созданную задачу с уникальным идентификатором и временной меткой.
2. **Получение списка задач** — клиент запрашивает все задачи, сервер возвращает массив задач в порядке создания (от новых к старым).
3. **Отметка о выполнении** — клиент отправляет PATCH-запрос с флагом `completed`, сервер обновляет статус задачи и возвращает обновлённую запись.
4. **Удаление задачи** — клиент отправляет DELETE-запрос по идентификатору, сервер удаляет запись и подтверждает операцию.

Система ориентирована на одного пользователя (без мультитенантности) и предназначена для локального или контейнерного развёртывания.

## 3. Архитектура

Приложение построено по классической трёхслойной архитектуре внутри одного сервиса. Внешних зависимостей, кроме базы данных, нет.

```
┌─────────────────────────────────────────────────────┐
│                     Клиент (HTTP)                    │
└────────────────────────┬────────────────────────────┘
                         │ HTTP/JSON
                         ▼
┌─────────────────────────────────────────────────────┐
│                  Uvicorn (ASGI)                      │
│                  Хост: 0.0.0.0:8000                  │
└────────────────────────┬────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────┐
│               FastAPI Application                    │
│  ┌─────────────────────────────────────────────┐    │
│  │            Слой API (Routers)                │    │
│  │  POST /tasks  GET /tasks  PATCH /tasks/{id}  │    │
│  │  DELETE /tasks/{id}                          │    │
│  └──────────────────────┬──────────────────────┘    │
│                         │                            │
│  ┌──────────────────────▼──────────────────────┐    │
│  │         Слой сервисов (Services)            │    │
│  │  TaskService — бизнес-логика                 │    │
│  └──────────────────────┬──────────────────────┘    │
│                         │                            │
│  ┌──────────────────────▼──────────────────────┐    │
│  │       Слой доступа к данным (Repository)     │    │
│  │  SQLAlchemy ORM + AsyncSession               │    │
│  └──────────────────────┬──────────────────────┘    │
└─────────────────────────┼───────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────┐
│              SQLite (tasks.db, WAL mode)             │
└─────────────────────────────────────────────────────┘
```

**Описание компонентов:**

- **Uvicorn** — ASGI-сервер, принимает HTTP-запросы и передаёт их в FastAPI-приложение. Запускается в одном процессе (для масштабирования — через `--workers`).
- **Слой API (Routers)** — принимает HTTP-запросы, валидирует входные данные через Pydantic-схемы, вызывает методы сервисного слоя, формирует HTTP-ответ. Не содержит бизнес-логики.
- **Слой сервисов (Services)** — содержит бизнес-логику: создание задачи, обновление статуса, удаление. Работает с сессиями БД, возвращая доменные объекты.
- **Слой доступа к данным (Repository)** — инкапсулирует SQLAlchemy-запросы. Предоставляет интерфейс для CRUD-операций над сущностью `Task`.
- **SQLite** — файловая база данных `tasks.db`. Хранит единственную таблицу `tasks`.

## 4. Модель данных

Система содержит единственную сущность — `Task`.

### Сущность `Task`

| Поле | Тип | Ограничения | Описание |
|------|-----|-------------|----------|
| `id` | Integer | Primary Key, Autoincrement | Уникальный идентификатор задачи. |
| `title` | String(500) | NOT NULL, длина 1–500 символов | Текст задачи. |
| `completed` | Boolean | NOT NULL, default = `false` | Флаг выполнения. |
| `created_at` | DateTime | NOT NULL, default = `utcnow()` | Время создания задачи (UTC). |
| `updated_at` | DateTime | NOT NULL, default = `utcnow()`, onupdate = `utcnow()` | Время последнего обновления. |

### Индексы

- Первичный ключ: `id` (создаётся автоматически).
- Индекс на `created_at DESC` — для оптимизации запроса списка задач, отсортированного по времени создания.

### Связи

Связи отсутствуют — модель содержит единственную сущность без внешних ключей.

### DDL (справочно)

```sql
CREATE TABLE tasks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title VARCHAR(500) NOT NULL,
    completed BOOLEAN NOT NULL DEFAULT 0,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_tasks_created_at ON tasks (created_at DESC);
```

## 5. API-контракты

Базовый путь: `/api/v1`. Все запросы и ответы используют `application/json`.

### 5.1. Создание задачи

```
POST /api/v1/tasks
```

**Тело запроса:**
```json
{
  "title": "Купить хлеб"
}
```

**Успешный ответ — 201 Created:**
```json
{
  "id": 1,
  "title": "Купить хлеб",
  "completed": false,
  "created_at": "2025-01-15T10:30:00Z",
  "updated_at": "2025-01-15T10:30:00Z"
}
```

**Ошибки:**

| Код | Условие | Тело ответа |
|-----|---------|-------------|
| 422 | `title` пустой или длиннее 500 символов | `{"detail": [{"loc": ["body","title"], "msg": "field required", "type": "value_error"}]}` |

---

### 5.2. Получение списка задач

```
GET /api/v1/tasks
```

**Параметры запроса:** отсутствуют.

**Успешный ответ — 200 OK:**
```json
[
  {
    "id": 2,
    "title": "Полить цветы",
    "completed": false,
    "created_at": "2025-01-15T11:00:00Z",
    "updated_at": "2025-01-15T11:00:00Z"
  },
  {
    "id": 1,
    "title": "Купить хлеб",
    "completed": true,
    "created_at": "2025-01-15T10:30:00Z",

  }

```

Задачи возвращаются отсортированными по `created_at DESC` (новые первыми). Если задач нет — возвращается пустой массив `[]` с кодом 200.


**Параметры пути:**
- `id` — целое число, идентификатор задачи.

## 6. Нефункциональные требования

### Безопасность

- Приложение не реализует аутентификацию и авторизацию в соответствии с требованиями (простой TODO-лист). При необходимости добавляется middleware с JWT-токенами.
- Включена встроенная защита FastAPI от CSRF для stateless API (только JSON-тела, без cookie-сессий).
- SQL-инъекции исключены использованием SQLAlchemy ORM с параметризованными запросами.
- Валидация входных данных через Pydantic предотвращает передачу некорректных типов и длин.
- Сервер слушает на `0.0.0.0:8000` — при продакшн-развёртывании рекомендуется reverse-proxy (nginx) с TLS.

### Производительность

- Использование асинхронных запросов к БД через `aiosqlite` драйвер.
- SQLite в режиме WAL (`PRAGMA journal_mode=WAL`) — обеспечивает конкурентное чтение без блокировок.
- Ожидаемая пропускная способность: до 1000 RPS на одном инстансе (с учётом локальной SQLite).
- Время ответа для всех эндпоинтов — не более 50 мс при размере таблицы до 100 000 записей.

### Масштабирование

- Вертикальное масштабирование: увеличение количества workers Uvicorn (`--workers N`).
- Горизонтальное масштабирование SQLite не поддерживает — при росте нагрузки требуется миграция на PostgreSQL (изменение только строки подключения, благодаря SQLAlchemy).
- Файл `tasks.db` хранится на локальном диске или в volume при контейнерном развёртывании.

### Надёжность

- Миграции БД выполняются через Alembic при каждом развёртывании.
- Все ошибки сервисного слоя перехватываются и преобразуются в HTTP-ответы с соответствующими кодами.
- Логирование через стандартный `logging` модуль Python (уровень INFO в продакшн, DEBUG в разработке).

### Совместимость

- API следует принципам REST.
- Формат обмена — JSON.
- Временные метки — ISO 8601 в формате UTC с суффиксом `Z`.

### Описание ключевых файлов

- **`app/main.py`** — создаёт экземпляр `FastAPI`, подключает роутеры `tasks` и `health`, настраивает обработку исключений (преобразование `TaskNotFoundError` в HTTP 404).
- **`app/database.py`** — создаёт `AsyncEngine` через `create_async_engine`, `async_sessionmaker`, и dependency `get_db`, отдающая асинхронную сессию. При старте выполняется `PRAGMA journal_mode=WAL`.
- **`app/models/task.py`** — декларативная SQLAlchemy-модель `Task` с полями, описанными в разделе 4.
- **`app/schemas/task.py`** — Pydantic-схемы: `TaskCreate` (поле `title`), `TaskUpdate` (поле `completed`), `TaskResponse` (все поля модели). Конфигурация `from_attributes=True` для маппинга из ORM-объекта.
- **`app/routers/tasks.py`** — четыре эндпоинта, описанных в разделе 5. Каждый вызывает соответствующий метод `TaskService`.
- **`app/services/task_service.py`** — методы `create_task`, `get_all_tasks`, `update_task`, `delete_task`. Принимает сессию БД, работает с `TaskRepository`, выбрасывает `TaskNotFoundError` при отсутствии записи.
- **`app/repositories/task_repository.py`** — методы `add`, `get_all`, `get_by_id`, `update`, `delete`. Инкапсулирует SQLAlchemy-запросы.
- **`app/exceptions/task_exceptions.py`** — класс `TaskNotFoundError(Exception)`.
- **`Dockerfile`** — образ на базе `python:3.11-slim`, устанавливает зависимости, запускает `uvicorn app.main:app --host 0.0.0.0 --port 8000`.
- **`docker-compose.yml`** — один сервис `api`, монтирует volume `./data:/app/data` для хранения `tasks.db`, пробрасывает порт 8000.
- **`.env.example`** — `DATABASE_URL=sqlite+aiosqlite:///./data/tasks.db`, `LOG_LEVEL=INFO`.
