# QA Gate

## Задача

        Проверь код Разработчика на соответствие архитектурному документу Архитектора.

        ЧТО ПРОВЕРЯТЬ:
        1. **Соответствие архитектуре**: все ли компоненты реализованы? Нет ли лишнего?
        2. **Безопасность**: SQL-инъекции, XSS, утечки секретов, небезопасные зависимости
        3. **Обработка ошибок**: все ли исключения обработаны? Нет ли голых try/except?
        4. **Валидация**: проверяются ли входные данные на всех endpoint-ах?
        5. **Тесты**: есть ли они? Покрывают ли основные сценарии?
        6. **Style guide**: PEP 8, нейминг, типизация

        ФОРМАТ ОТВЕТА:
        Для каждой найденной проблемы:
        - Приоритет: 🔴 (критично — блокирует запуск) / 🟡 (важно — нужно исправить) / 🟢 (минор — можно так)
        - Файл и строка (если применимо)
        - Описание проблемы
        - Предложение по исправлению

        В конце: ИТОГОВЫЙ ВЕРДИКТ — ✅ Go (нет критических проблем) или ❌ No-Go (требуются правки).
        Если No-Go — перечисли КОНКРЕТНЫЕ файлы и строки, которые нужно исправить.
        

## Результат

## Отчёт о проверке кода

### 🔴 Критично

1. **Файл:** `src/main.py`, строка 63  
   **Проблема:** Отсутствует импорт `text` из SQLAlchemy. В функции `health_check` используется `text("SELECT 1")`, но `text` не импортирован. Это вызовет `NameError` при обращении к `/health`.  
   **Исправление:** Добавить `from sqlalchemy import text` в начало файла.

---

### 🟡 Важно

2. **Файл:** `src/api/v1/router.py`, строка 10  
   **Проблема:** Все эндпоинты имеют префикс `/v1`, тогда как архитектурный документ (раздел 5) определяет пути без версионирования: `POST /shorten`, `GET /{short_id}`, `GET /stats/{short_id}`, `DELETE /{short_id}`. Это несоответствие архитектуре.  
   **Исправление:** Убрать префикс `/v1` из роутера или согласовать изменение архитектурного документа.

3. **Файл:** `src/models/url.py`, строки 20–35  
   **Проблема:** Модель `Url` не содержит индексов на `created_at` и partial index на `deleted_at`, хотя они описаны в архитектуре (раздел 4.2) и созданы в миграции `001_initial_schema.py`. При автогенерации миграций из модели эти индексы будут потеряны.  
   **Исправление:** Добавить в `__table_args__` модели индексы:
   ```python
   Index('idx_urls_created_at', 'created_at'),
   Index('idx_urls_deleted_at', 'deleted_at', postgresql_where=text('deleted_at IS NULL'))
   ```

4. **Файл:** `src/services/stats_flusher.py`, строка 26  
   **Проблема:** Background task сбрасывает счётчики только по таймеру (60 секунд), но архитектура (раздел 3.2) также требует сброса при достижении порога в 100 переходов.  
   **Исправление:** Добавить проверку порога в `flush_counters` или в `increment_click` (например, после инкремента проверять значение и при превышении 100 вызывать немедленный flush).

5. **Файл:** `src/api/v1/redirect.py`, строка 35  
   **Проблема:** `asyncio.create_task(stats_service.increment_click(short_id))` не обрабатывает возможные исключения. При ошибке в Redis задача упадёт молча, счётчик будет потерян.  
   **Исправление:** Обернуть вызов в try/except и логировать ошибку:
   ```python
   async def _increment(short_id: str):
       try:
           await stats_service.increment_click(short_id)
       except Exception:
           logger.exception("Failed to increment click counter")
   asyncio.create_task(_increment(short_id))
   ```

6. **Файл:** `tests/conftest.py`, строки 40–50  
   **Проблема:** Middleware `RateLimitMiddleware` создаётся при старте приложения с реальным `redis_client`, а не с `FakeRedis`. Dependency overrides влияют только на эндпоинты, но не на middleware. Тесты rate limit (например, `test_shorten_rate_limit`) будут использовать настоящий Redis, что делает их недетерминированными и ломает изоляцию.  
   **Исправление:** В тестах создавать приложение заново с подменённым `redis_client` в middleware, либо переписать middleware так, чтобы он получал Redis через dependency injection.

7. **Файл:** `tests/integration/test_shorten.py`, строки 30–40  
   **Проблема:** Тест `test_shorten_rate_limit` использует `monkeypatch` для изменения `settings.rate_limit_requests`, но middleware уже инициализирован с оригинальными значениями. Изменение `settings` после создания middleware не влияет на его поведение.  
   **Исправление:** Пересоздавать приложение с новыми настройками или передавать лимиты через параметры middleware.

---

### 🟢 Минор

8. **Файл:** `src/models/url.py`, строка 12  
   **Проблема:** Вместо `server_default=text("gen_random_uuid()")` используется `default=uuid.uuid4`. Это не соответствует архитектуре (раздел 4.1), где указан `DEFAULT gen_random_uuid()`. Разница не критична, но лучше использовать server_default для единообразия.  
   **Исправление:** Заменить на `server_default=text("gen_random_uuid()")`.

9. **Файл:** `src/models/url.py`, строка 24  
   **Проблема:** Добавлен `UniqueConstraint("short_id", name="uq_short_id")`, хотя колонка уже объявлена как `unique=True`. Это избыточно.  
   **Исправление:** Убрать `UniqueConstraint` или оставить, но это не влияет на функциональность.

10. **Файл:** `.gitignore` отсутствует  
    **Проблема:** Архитектура (раздел 6.1) требует, чтобы `.env` файл был в `.gitignore`. В проекте нет `.gitignore`.  
    **Исправление:** Добавить `.gitignore` с типовыми правилами для Python (включая `.env`, `__pycache__`, `*.pyc` и т.д.).

11. **Файл:** `src/config.py`, строка 30  
    **Проблема:** `cors_origins` по умолчанию `"*"`. В production это небезопасно, но настраивается через env. Минор, так как архитектура допускает настройку.  
    **Исправление:** Оставить как есть, но добавить комментарий о необходимости ограничения в production.
