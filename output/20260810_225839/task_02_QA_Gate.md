# QA Gate

## Задача

        Проверь код Разработчика на соответствие архитектурному документу Архитектора.

        ЧТО ПРОВЕРЯТЬ:
        1. **Соответствие архитектуре**: все ли компоненты реализованы? Нет ли лишнего?
        2. **Безопасность**: SQL-инъекции, XSS, утечки секретов, небезопасные зависимости
        3. **Обработка ошибок**: все ли исключения обработаны? Нет ли голых try/except?
        4. **Валидация**: проверяются ли входные данные на всех endpoint-ах?
        5. **Тесты**: есть ли они? Покрывают ли основные сценарии?
        6. **Style guide**: PEP 8, нейминг, типизация

        ФОРМАТ ОТВЕТА:
        Для каждой найденной проблемы:
        - Приоритет: 🔴 (критично — блокирует запуск) / 🟡 (важно — нужно исправить) / 🟢 (минор — можно так)
        - Файл и строка (если применимо)
        - Описание проблемы
        - Предложение по исправлению

        В конце: ИТОГОВЫЙ ВЕРДИКТ — ✅ Go (нет критических проблем) или ❌ No-Go (требуются правки).
        Если No-Go — перечисли КОНКРЕТНЫЕ файлы и строки, которые нужно исправить.
        

## Результат

## Отчёт о проверке кода URL Shortener Microservice

### 🔴 Критические проблемы (блокируют запуск)

1. **Ошибка импорта `get_async_session`**
   - **Файлы:** `app/routers/shorten.py`, `app/routers/redirect.py`, `app/routers/stats.py`, `app/routers/delete.py`, `app/dependencies.py`
   - **Описание:** Роутеры импортируют `get_async_session` из `app.dependencies`, но в этом файле функция не определена (файл содержит только комментарий). При запуске приложения возникнет `ImportError`, что полностью блокирует работу сервиса.
   - **Исправление:** Добавить реэкспорт в `app/dependencies.py`:
     ```python
     from app.database import get_async_session
     ```
     Или заменить импорты в роутерах на `from app.database import get_async_session`.

2. **Rate limiter в `POST /shorten` не имеет параметра `request`**
   - **Файл:** `app/routers/shorten.py`, функция `create_short_url`
   - **Описание:** slowapi требует, чтобы функция с декоратором `@limiter.limit()` содержала параметр `request: Request`. В текущей сигнатуре он отсутствует, что приведёт к ошибке `ValueError` при первом обращении к эндпоинту. `POST /shorten` — основной сценарий сервиса, поэтому это критично.
   - **Исправление:** Добавить параметр `request: Request` в сигнатуру функции:
     ```python
     async def create_short_url(
         request: Request,
         request_data: ShortenRequest,
         session: AsyncSession = Depends(get_async_session),
         redis: aioredis.Redis = Depends(get_redis_client),
     ) -> ShortenResponse:
     ```

### 🟡 Важные проблемы (нужно исправить до продакшена)

3. **Не реализована фоновая синхронизация кликов из Redis в PostgreSQL**
   - **Файлы:** `app/main.py`, `app/services/sync_service.py`
   - **Описание:** Архитектурный документ требует периодическую (раз в 5 минут) синхронизацию счётчиков из Redis в БД. Код `SyncService` написан, но не вызывается в `lifespan` приложения. В результате при cache hit клики накапливаются только в Redis, а в PostgreSQL `click_count` остаётся устаревшим. Это приводит к некорректной статистике.
   - **Исправление:** В `app/main.py` в `lifespan` запустить фоновую задачу:
     ```python
     @asynccontextmanager
     async def lifespan(app: FastAPI):
         task = asyncio.create_task(sync_service.start(...))
         yield
         task.cancel()
         await engine.dispose()
     ```

4. **Redis клиент создаёт новый пул соединений на каждый запрос**
   - **Файл:** `app/redis_client.py`, функция `get_redis_client`
   - **Описание:** Вместо переиспользования глобального пула создаётся новый `ConnectionPool` на каждый запрос, а затем закрывается. Это неэффективно и может привести к исчерпанию соединений при высокой нагрузке.
   - **Исправление:** Создать глобальный экземпляр `redis.asyncio.Redis` и использовать его в зависимости:
     ```python
     redis_client = aioredis.Redis.from_url(settings.redis_url, max_connections=10)

     async def get_redis_client():
         return redis_client
     ```

5. **Коллизии short_code с удалёнными записями не обрабатываются**
   - **Файл:** `app/services/url_service.py`, метод `shorten_url`
   - **Описание:** Проверка существования кода использует `get_by_short_code`, который фильтрует по `is_deleted == False`. Если сгенерированный код совпадает с мягко удалённой записью, проверка не увидит её, а `create` выбросит необработанный `IntegrityError` (из-за UNIQUE constraint). Вероятность мала, но при большом количестве удалений возможна.
   - **Исправление:** Либо проверять существование кода без фильтра `is_deleted`, либо ловить `IntegrityError` в цикле генерации и повторять попытку.

6. **Отсутствует обработка сбоев Redis/БД в сервисном слое**
   - **Файлы:** `app/services/url_service.py` (методы `get_redirect_url`, `get_stats`, `delete_url`)
   - **Описание:** Если Redis недоступен, при cache hit будет выброшено исключение, и вместо фолбэка на БД вернётся 500. Аналогично при сбое PostgreSQL — нет переключения на Redis. Для отказоустойчивости нужен graceful degradation.
   - **Исправление:** Обернуть операции с Redis в `try/except` с логированием и переходом к БД; обернуть операции с БД в `try/except` с возвратом 503 или повторной попыткой.

7. **Race condition при синхронизации кликов**
   - **Файл:** `app/services/sync_service.py`, метод `sync_clicks`
   - **Описание:** Между `HGET` и `HDEL` может произойти новый инкремент, и тогда `HDEL` удалит и новое значение, что приведёт к потере кликов. Необходимо атомарное извлечение и удаление.
   - **Исправление:** Использовать Lua-скрипт:
     ```lua
     local v = redis.call('HGET', KEYS[1], 'clicks')
     if v then redis.call('HDEL', KEYS[1], 'clicks') end
     return v
     ```
     Или использовать `HGETDEL` (в новых версиях Redis 7+).

8. **Тесты не соответствуют реализации**
   - **Файлы:** `tests/test_shorten.py`, `tests/test_stats.py`
   - **Описание:**
     - `test_shorten_url_success` ожидает `short_url` с префиксом `http://test/`, но `settings.base_url` по умолчанию `http://localhost:8000` → тест упадёт.
     - `test_shorten_url_with_expiration` ожидает `expires_at` без `+00:00`, но Pydantic сериализует datetime с таймзоной → тест упадёт.
     - `test_stats_success` ожидает `click_count == 3`, но при cache hit клики не попадают в БД (синхронизация не запущена) → тест упадёт.
   - **Исправление:** Переопределить `settings.base_url` в тестах, скорректировать ожидаемые значения datetime и либо включить синхронизацию в тестовом окружении, либо изменить тест, чтобы он учитывал Redis-счётчик.

9. **CORS разрешает методы, не предусмотренные архитектурой**
   - **Файл:** `app/main.py`
   - **Описание:** Архитектура говорит: "по умолчанию разрешены только GET-методы для редиректов", но в коде `allow_methods=["GET", "POST", "DELETE", "OPTIONS"]`. Это не является прямой угрозой, но противоречит документу.
   - **Исправление:** Ограничить до `["GET", "OPTIONS"]`, если это действительно требуется архитектурой.

### 🟢 Минорные проблемы

10. **Неиспользуемые импорты**
    - `app/main.py` — `Base` из `app.database` не используется.
    - `app/repositories/url_repository.py` — `List` импортирован, но не используется.
    - `app/services/sync_service.py` — `AsyncSessionLocal` импортирован, но не используется.
    - **Исправление:** Удалить лишние импорты.

11. **Дублирующий индекс на `short_code`**
    - **Файл:** `app/models/url.py`, поле `short_code`
    - **Описание:** `unique=True` уже создаёт уникальный индекс, а `index=True` добавляет ещё один обычный индекс — избыточно.
    - **Исправление:** Убрать `index=True`.

12. **Нет валидации short_code в роутерах**
    - **Файлы:** `app/routers/redirect.py`, `app/routers/stats.py`, `app/routers/delete.py`
    - **Описание:** Параметр `short_code` принимается как строка любой длины. Можно добавить валидацию через `Path(pattern=r"^[a-zA-Z0-9]{6}$")`, чтобы отсечь заведомо невалидные запросы.
    - **Исправление:** Добавить паттерн валидации или оставить как есть (безопасно, но менее производительно).

13. **Нет логирования запросов**
    - **Файл:** `app/main.py`
    - **Описание:** Архитектурный документ упоминает логирование в middleware, но в коде оно отсутствует.
    - **Исправление:** Добавить middleware для логирования (например, `structlog` или стандартный `logging`).

14. **Health check не проверяет версию БД/Redis**
    - **Файл:** `app/routers/health.py`
    - **Описание:** Проверяется только `SELECT 1` и `ping()`, что достаточно для базовой проверки, но не проверяет доступность миграций.
    - **Исправление:** Опционально, можно не менять.

15. **`docker-compose.yml` не имеет healthcheck для app**
    - **Файл:** `docker-compose.yml`
    - **Описание:** Для оркестрации полезно добавить healthcheck на основе `/health`, но это не критично.

### ИТОГОВЫЙ ВЕРДИКТ

## ❌ No-Go

Требуются обязательные правки перед запуском:

1. **`app/dependencies.py`** — добавить `get_async_session` (или заменить импорты в роутерах на `app.database`).
2. **`app/routers/shorten.py`** — добавить параметр `request: Request` в функцию `create_short_url`.
3. **`app/main.py`** — запустить фоновую задачу синхронизации кликов (`SyncService`).
4. **`app/redis_client.py`** — переиспользовать глобальный Redis-пул.
5. **`app/services/url_service.py`** — обработать коллизии с удалёнными кодами и сбои Redis/БД.
6. **`app/services/sync_service.py`** — устранить race condition (Lua-скрипт).
7. **`tests/test_shorten.py`, `tests/test_stats.py`** — исправить тесты под актуальное поведение.

После исправления критических пунктов (1–2) сервис сможет запуститься, но для соответствия архитектуре и стабильной работы необходимо закрыть все пункты из списка важных.
