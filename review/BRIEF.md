# AI Team Corporation — обзор для code review

> **Цель проекта:** AI-команда (Архитектор → Разработчик → QA Gate → DevOps) генерирует код по описанию на естественном языке, прогоняет тесты, создаёт Docker-образ и открывает PR с CI/CD.  
> **Стек:** Python 3.12, CrewAI 1.15, OpenRouter, FastAPI, Docker  
> **Бюджет одного прогона:** ~$0.08–0.10 | **Максимум:** $0.15

---

## Архитектура — конвейер из 5 шагов

```
Пользователь → main.py → CrewAI (Process.sequential)
  1. Архитектор (GLM-5.2)        — проектирует систему, пишет архитектурный документ (markdown)
  2. Разработчик (DeepSeek V4 Pro) — пишет код, возвращает JSON {files: [{path, content}]}
  3. QA Gate (Codestral 2508)     — ревьюит код: 🔴/🟡/🟢 приоритеты, вердикт ✅Go/❌No-Go
  4. Разработчик (повторно)       — исправляет замечания QA, возвращает полную кодовую базу JSON
  5. DevOps (DeepSeek V4 Pro)     — Dockerfile, docker-compose.yml, .env.example, README.md, CI/CD
```

Все 5 шагов идут последовательно. После CrewAI оркестратор (main.py) делает:
- **Деплой и верификацию** — `docker compose up`, healthcheck, pytest
- **Pull Request** — создаёт ветку `ai-team/<timestamp>`, пушит код, открывает PR через GitHub API

## Ключевые архитектурные решения (оценить)

### 1. JSON-выдача вместо regex-парсинга markdown
**Проблема (было):** regex-парсинг markdown-блоков ловил мусор: box-drawing символы, версии зависимостей, HTTP-статусы, пустые блоки. До 50% артефактов — мусор.  
**Решение (стало):** `output_pydantic=CodeOutput` на задачах Разработчика и DevOps. Модель возвращает JSON `{files: [{path, content}]}`. В `_extract_files()` JSON-first, regex — только fallback.  
**Результат:** 0 мусорных файлов в последнем прогоне. 21 файл — все настоящие.
**Код:** `main.py:138-204`, `output_models.py`, `tasks.py:73,120,159`

### 2. DevOps генерирует CI/CD
**Проблема (было):** CI/CD чинился вручную. Неправильно.  
**Решение (стало):** В промпт DevOps-задачи (`tasks.py:123-160`) добавлена генерация `.github/workflows/ci.yml`.  
**⭐ Результат:** В последнем прогоне (URL Shortener 07:25) CI/CD **сгенерировался впервые**:
```yaml
name: CI/CD
on: push (master, ai-team/**), pull_request (master)
jobs:
  test: Python 3.12, venv, pytest --tb=short  ← БЕЗ || true
  build: docker build (только push в master/ai-team)
```
Чистый, правильный CI. До этого 3 прогона — без CI.

### 3. `.collision`-защита при конфликтах имён
**Ситуация:** Разработчик и DevOps могут сгенерировать файлы с одинаковыми именами.  
**Решение:** `_write_file_safe()` — если файл существует, создаётся дубликат с суффиксом `.collision`.  
**Вопрос для ревью:** насколько это адекватно? Может, лучше сравнивать содержимое и перезаписывать при совпадении?
**Код:** `main.py:102-135`

### 4. Безопасный деплой — определение имени контейнера
**Проблема (было):** жёстко зашито `docker exec <project>_app_1`.  
**Решение (стало):** `docker compose config --services` → фильтрация инфраструктурных сервисов (db, redis, postgres) → `docker compose ps -q <service>`.  
**Код:** `main.py:335-355`

### 5. Fallback тестов с хоста
**Проблема:** DevOps не всегда копирует `tests/` в образ.  
**Решение:** если `docker exec ... pytest tests/` не находит тестов, запускаем `pytest` с хоста из `run_dir`.  
**Код:** `main.py:358-379`

## Известные проблемы (для оценки)

1. **Контейнер падает при старте** — в последнем прогоне контейнер exited (3). Приложение крашится, хотя QA-замечания исправлены. Нужна диагностика.

2. **Подсчёт токенов приблизительный** — CrewAI не всегда возвращает `usage`. В `on_task_complete()` есть fallback на `len(text)//4`, но это грубая оценка.
   **Код:** `main.py:58-84`

3. **`.collision` вместо осмысленного разрешения конфликтов** — сейчас просто создаётся дубликат. Может быть лучше: сравнить содержимое → перезаписать, если идентично; смержить, если конфликт реальный.

4. **Healthcheck в деплое жёстко завязан на `/openapi.json`** — не все сервисы реализуют этот эндпоинт.
   **Код:** `main.py:322`

5. **Проверка портов перед деплоем жёсткая (8000, 5432, 6379)** — не хватает динамики.
   **Код:** `main.py:275-281`

6. **`on_task_complete()`**: оценка токенов по символам с ценой модели — даёт неточную стоимость. Но альтернативы без реального `usage` от API нет.
